## 1. 这是什么项目

QBase 是**本地优先的个人知识库管理应用**：打开一个本地目录作为「知识库」，自动扫描其中的音视频与文档，识别转录、总结、笔记等派生文件，在浏览器里提供三层搜索（文件名 / 全文 / 语义）、AI 总结、标签管理与媒体播放。

核心设计理念——**文件系统是唯一数据源**：

- 用户的所有内容始终是磁盘上的普通文件，不锁进私有数据库
- 应用产生的元数据、索引、缓存全部落在知识库目录下的 `.knowledge/` 里
- 删掉 `.knowledge/` 整个目录，重新扫描即可重建资产清单（标签除外，见 §11 已知限制）
- 换机器、换软件，原文直接可用

技术栈：Python 3.12 + uv（虚拟环境）、NiceGUI（UI，基于 FastAPI + uvicorn）、SQLite（元数据 + FTS5 全文索引）、LanceDB（向量）、loguru（日志）。运行在 Windows 本机，浏览器访问 `http://127.0.0.1:8765`。

## 3. 功能全景（用户视角）

**知识库管理**：首页输入任意本地目录打开；首页展示最近打开的 5 个知识库一键切换。

**扫描与资产**：识别 7 种音频（mp3/m4a/wav/flac/aac/ogg/opus）、5 种视频（mp4/mkv/mov/webm/avi）、12 种文档（pdf/docx/doc/pptx/ppt/xlsx/xls/md/txt/html/htm/epub）为「资产」；资产列表支持类型/文件名/标签筛选、排序、分页、派生状态徽章。

**派生文件识别**：与资产同名同目录的 sidecar 文件自动绑定——`.transcript.txt` / `.transcript.json`（转录）、`.summary.md`（总结）、`.notes.md`（笔记）、`.parsed.md`（解析产物）、`.meta.json`（元数据）；M11 起也识别 `<原始文件名>.kb/` 派生目录（总结/解析产物跟随写入）。JSON 转录自动提取纯文本用于索引与总结，时间轴保留原文件。

**转录**：详情页手动触发，调用外部转录 CLI（默认同级仓库 QVoice，输出带时间戳/说话人的 JSON），后台任务化，并发去重、失败可重试。

**文档解析**：PDF 与 Office（docx/doc/pptx/ppt/xlsx/xls）走 MinerU 云 API（批量上传、断点恢复轮询）；EPUB 走内置本地解析器（标准库实现，免 token 秒级完成）；产物 `parsed.md` 进入全文/向量索引。

**AI 总结**：详情页一键对文档或转录生成总结（OpenAI 兼容 LLM），长文自动分段摘要再合并，覆盖前自动备份到 `.knowledge/backups/`。

**搜索（三层 + 融合）**：

| 模式 | 实现 |
|---|---|
| 文件名 | 标题/路径 LIKE |
| 全文 | SQLite FTS5，中文子串 LIKE 兜底；命中高亮 |
| 语义 | LanceDB 向量 + OpenAI 兼容 Embedding，带缓存不重复计费 |
| 综合（默认） | 全文+向量两路 RRF 融合（k=60），chunk 级去重，双命中排前并标注来源；单路不可用自动降级不报错 |

四种模式均支持**标签过滤**（多选，任一命中）。

**标签系统（M15）**：详情页手动打标（下拉可选、可输入新名称）；新标签自动创建，零引用标签自动清理；纯扁平标签，无层级/颜色/管理页。**AI 建议标签（M16）**：详情页「AI 建议标签」按钮调 LLM（独立 `[llm.tagging]` 配置，可与总结用不同模型）生成建议预填编辑器，确认保存才入库。

**批量任务（M17）**：资产列表多选（跨页保留）后可批量总结（弹窗选「跳过已有」或「全部重新生成」+ 自动备份）与批量 AI 打标（建议清洗后自动**追加**写库、不删已有标签，写入内容记入任务详情可审计）；逐资产进任务中心，失败可重试，重启自动恢复未完结任务；并发走 `[task].max_workers`（默认 1 串行）。批量入口只做已有能力的批量版，不含批量转录/解析。

**播放器（M13）**：音视频详情页原生播放器；JSON 转录分段时间戳可点击跳转（seek + play）。

**设置页 + 任务中心**：LLM/Embedding/Index/Task/Library 高频配置表单化编辑（写回 `config.toml`），CLI/App 只读展示 + 一键打开配置文件；密钥来源红绿灯检测、API 连通性测试、dimension/model 变更重建告警；向量索引健康卡片（模型/维度/覆盖度/最后重建）。任务中心查看转录/总结/解析任务详情、失败重试，5 秒自动刷新。

**UI 体系**：全站统一 page_frame 布局 + 设计 token（`app/ui/tokens.py` 单一来源，WCAG AA 灰度对比度）。

## 4. 架构与代码结构

分层：`UI（NiceGUI）→ REST API（FastAPI）→ Service 业务层 → Repository 数据访问 → SQLite / LanceDB / 文件系统`；重活（转录/总结/解析）走后台任务线程。

```text
app/                     # 46 个 py 文件，约 9700 行
├── main.py              # 入口：create_app + uvicorn
├── config.py            # 应用级配置（config.toml + QBASE_* 环境变量）
├── state.py             # 运行时状态（当前知识库 / 数据库路径）
├── database.py          # SQLite 连接与建表（WAL，8 表 + FTS5）
├── rules.py             # 文件类型 / 派生规则 / .kb 目录判定
├── utils.py             # 格式化 / 文本读取 / JSON 转录提取 / 高亮
├── api/                 # REST 路由：library.py（业务端点）、settings.py
├── repositories/        # 数据访问：asset / artifact / task / tag
├── services/            # 业务层：library / scanner / transcription / parse
│                        #   / summarization / index / search / vector / llm
│                        #   / cli_runner / config / tag / batch_runner / recent_library
│   └── parsers/         # 解析器注册表：MinerU（云）/ EPUB（本地）
└── ui/                  # layout.py（page_frame）+ tokens.py（设计 token）
                         #   + components.py（共享徽章）+ pages/ 六个页面
```

数据库表（`<库>/.knowledge/db.sqlite`）：`assets`（资产）、`artifacts`（派生文件）、`tasks`（任务）、`chunks`（分块）、`chunks_fts`（FTS5 全文索引）、`embedding_cache`（向量缓存）、`tags` / `asset_tags`（标签，M15）。向量数据在 `.knowledge/vector/lancedb`。

## 5. API 一览（前缀 /api）

| 分组 | 端点 |
|---|---|
| 知识库 | `POST /library/open` `POST /library/close` `GET /library/status` `POST /library/scan` |
| 资产 | `GET /assets` `GET /assets/{id}`（含标签） |
| 资产操作 | `POST /assets/{id}/transcribe` `POST /assets/{id}/summarize` `POST /assets/{id}/parse` `POST /assets/{id}/sidecar-dir`（建 .kb 目录） |
| 批量（m17） | `POST /assets/batch-summarize`（body {asset_ids, overwrite}） `POST /assets/batch-tag`（body {asset_ids}） |
| 标签 | `GET /tags` `PUT /assets/{id}/tags`（整体替换） `POST /assets/{id}/suggest-tags`（AI 建议，只返回不写库） |
| 搜索 | `GET /search?q&mode&limit&tag`（mode=filename/fulltext/vector/hybrid，tag 可重复） |
| 索引 | `POST /search/rebuild`（全文） `POST /search/vector/rebuild`（向量） |
| 任务 | `GET /tasks` `GET /tasks/{id}` |
| 设置 | `GET/PUT /settings` `POST /settings/test-connection` |

## 6. 配置体系与密钥

**应用级**（仓库根 `config.toml`，可用 `QBASE_HOST/PORT/LOG_LEVEL/OPEN_BROWSER` 覆盖）：仅运行参数（host/port/日志/是否自动开浏览器）。

**知识库级**（`<库>/.knowledge/config.toml`，首次打开自动生成模板，设置页可表单编辑）：`[library]`（扫描开关/忽略目录）、`[task]`（并发/超时）、`[cli]`（转录命令，默认 QVoice `-f json`）、`[parse]`（MinerU token/模型/超时）、`[llm.summary]`、`[llm.tagging]`（AI 打标，m16）、`[embedding]`、`[index]`（分块参数）。

**密钥红线**：配置里只写环境变量名（`api_key_env` / `token_env`），实际密钥走系统环境变量或 `.knowledge/secrets.toml`（gitignore 内）；UI 永不出现明文 Key，接口返回一律打码。**所有远程 API（转录除外）默认 `enabled = false`**，防止误触发费用。

## 7. 如何运行

```bash
uv sync                              # 安装依赖（Python 3.12，venv 在 .venv/）
.venv/Scripts/python.exe -m app.main # 启动，或直接双击 start.bat
# 浏览器访问 http://127.0.0.1:8765
```

使用流程：首页打开目录 → 扫描 → （可选）转录 / 解析 / 总结 → 搜索页四模式检索。语义搜索首次使用前到设置页「重建向量索引」。

## 8. 关键设计决策（为什么是这样）

- **配置唯一真相源 = 文件**：设置页保存走「读原配置 → deep merge → 写回 config.toml」，不进数据库，未编辑字段与未来新增字段都保留
- **索引是缓存不是数据**：全文/向量索引全量清空重建，坏了就重建，不做增量同步（个人库规模够用）
- **FTS5 + LIKE 兜底**：FTS5 默认分词对中文子串不可靠，中文查询降级 LIKE 逐行扫，个人库规模可接受
- **RRF k=60**：混合搜索取 RRF 论文标准值，两路等权，不做权重调参
- **任务模型**：重试 = 创建新任务（保留完整历史）；同资产同类型存在 pending/running 任务时拒绝（HTTP 400 去重）；批量任务（m17）也逐资产走这套模型，新任务类型 `tagging`，重启后 pending/running 任务幂等恢复
- **标签仅存 SQLite**：不做 tags.json 双写（.knowledge 本就声明可删重建）；ID 用 uuid5(标签名)，同名重建同 ID
- **AI 打标只建议不写库**（m16 单条流程）：LLM 结果经宽松清洗后预填编辑器，用户确认保存才入库；**批量打标（m17）例外**——自动追加写库但绝不删除已有标签，写入内容记入任务参数可审计；打标走独立 `[llm.tagging]` 配置，可与总结用不同模型
- **手动优先**：扫描、转录、总结、解析全部手动触发，不做 watch 自动同步（暂缓）、不做自动转录
- **范围纪律**：PRD §3「明确不做」清单 + 每个里程碑讨论稿先定「范围外」，防止蔓延

## 11. 已知限制

- 删除 `.knowledge/` 会丢失**标签**（资产清单与索引可重建，标签没有文件侧备份——已知取舍）
- 向量搜索叠加标签过滤时，过滤发生在 top-K 回表之后，结果可能少于 limit（预期行为）
- HTML/HTM 列为文档资产但**无内容提取**（状态「无需解析」，仅文件名搜索，内容不进索引）
- 设置页 CLI/App 段为只读展示，改这两个要手动编辑 config.toml
- 首页里程碑卡只展示到 M8（后续里程碑未加入，刻意不动）
- Windows 优先：路径/GBK 编码问题已专门处理（PYTHONUTF8 注入等），其他平台未验证
