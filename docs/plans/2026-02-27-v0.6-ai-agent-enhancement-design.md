### 1.2 实施策略：B+ 架构方案详解

#### 什么是 B+ 架构？

B+ 架构是 **方案 B（MVP 快速迭代）** 与 **方案 C（能力优先整合）** 的结合体：

```
方案 A：瀑布式（逐个完成，周期长）
方案 B：MVP 迭代（快速验证，反馈循环）← 核心
方案 C：架构优先（接口统一，扩展性强）← 预埋
      ↓
B+ 架构 = 方案 B 的速度 + 方案 C 的扩展性
```

---

| **上线速度** | ⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ | **⭐⭐⭐⭐** |

---

#### B+ 架构的三大原则

**原则 1：接口先行，实现在后**
- 先定义 `DocumentProcessor`、`VectorStore` 等统一接口
- 初期用简单实现（云端 API + 内存存储）
- 后期可无缝替换为强大实现（本地模型 + 向量数据库）

**原则 2：MVP 快速验证**
- 每个版本只做 1-2 个核心功能
- 上线后收集用户反馈
- 下一个版本迭代优化

**原则 3：可插拔设计**
- 所有实现都通过接口抽象
- 云端 / 本地实现可配置切换
- 不影响上层业务逻辑

#### 关键好处

1. **无需重写**：上层业务逻辑（AI 问答、闪卡生成等）完全不用改
2. **可插拔**：解析器、向量存储都可以独立替换升级

4. **快速反馈**：用户能快速体验新功能，反馈循环快

## 四、API 集成方案

### 4.1 MinerU API（PDF 解析）

**API 文档**: `official_docs/api/mineru_api.md`

**特点**:
- 批量上传 + 异步任务 + 轮询结果
- 输出：Markdown、JSON、可选 DOCX/HTML
- 支持：PDF、DOC、PPT、图片、HTML

**集成流程**（需要 Electron 主进程支持）:
```
渲染进程 → IPC → 主进程：
1. 读取本地文件
2. 调用 MinerU 申请上传链接
3. PUT 上传文件
4. 提交解析任务
5. 轮询任务状态
6. 下载解析结果 ZIP
7. 返回 Markdown 文本
```

### 4.2 SiliconFlow API（语音转录 + Embedding）

**API 文档**: `official_docs/api/siliconflow.md`

**特点**:
- OpenAI 兼容 API
- `/audio/transcriptions` - 语音转文字（Whisper 兼容）
- `/v1/embeddings` - 向量嵌入（OpenAI 兼容）

**推荐模型**:
- 语音转录：`FunAudioLLM/SenseVoiceSmall`
- 向量化：`BAAI/bge-large-zh-v1.5`

## 五、关键接口设计

### 5.1 DocumentProcessor 接口

```javascript
// app/src/processors/DocumentProcessor.js

export interface DocumentProcessor {
  extractText(file: File): Promise<string>
  extractStructured(file: File): Promise<StructuredDocument>
}

export interface StructuredDocument {
  markdown: string
  json: any
  title?: string
  sections?: Section[]
}

export interface Section {
  id: string
  title: string
  content: string
  level: number
}
```

### 5.2 VectorStore 接口

```javascript
// app/src/stores/vector.js

export interface VectorStore {
  addDocument(doc: Document): Promise<void>
  search(query: string, k?: number): Promise<SearchResult[]>
  clear(): Promise<void>
}

export interface Document {
  id: string
  content: string
  metadata?: Record<string, any>
  embedding?: number[]
}

export interface SearchResult {
  id: string
  content: string
  score: number
  metadata?: Record<string, any>
}
```
