# 解析管理 UI/UX 重构设计

**状态**: 📋 待实施  
**创建日期**: 2026-03-07  
**设计目标**: 优化解析管理和向量索引的用户体验

---

## 1. 设计背景与目标

### 1.1 问题分析

当前实现存在以下问题：
- 解析任务和向量索引分离在两个标签页中，用户需要切换查看同一文件的状态
- 左侧导航栏 + 内部标签页的双重导航结构复杂
- 缺乏统一的文件管理视图
- 看板功能缺失

### 1.2 设计目标

- ✅ 以文件为中心的统一视图
- ✅ 简化导航结构，采用顶部标签页
- ✅ 提供列表和看板两种视图模式
- ✅ 侧边抽屉展示分块详情
- ✅ 保留所有现有功能（WebSocket、批量操作、统计等）

---

## 2. 用户需求分析

基于用户提出的两个设计想法，我们总结出核心需求：

### 2.1 功能需求
1. 文本解析状态管理
2. 向量索引状态管理
3. 看板视图（宏观概览）
4. 分块详情查看
5. 筛选和搜索功能

### 2.2 非功能需求
1. 直观的用户界面
2. 高效的工作流
3. 实时状态更新
4. 响应式布局

└─────────────────────────────────────────────────────────────────┘

**表格列说明**:
| 列名 | 说明 | 显示内容 |
|------|------|----------|
| 文件名 | 文件图标 + 文件名 | 带图标的文件名，hover 显示完整路径 |
| 文本解析状态 | 解析进度和状态 | 状态徽章 + 进度条（进行中时） |
| 向量索引状态 | 索引进度和状态 | 状态徽章 + 进度条（进行中时） |
| 分块数 | 向量分块数量 | 数字（已索引时显示） |
| 操作 | 文件操作按钮 | 详情、重试、索引、删除等 |

**状态徽章设计**:
| 状态 | 图标 | 颜色 | 说明 |
|------|------|------|------|
| 待解析 | ⏸ | gray | 等待处理 |
| 解析中 | 🔄 | blue | 解析进行中，带进度条 |
| 已完成 | ✅ | green | 解析成功 |
| 失败 | ❌ | red | 解析失败 |
| 索引中 | ⏳ | blue | 向量索引进行中 |
| 已索引 | ✅ | green | 向量索引完成 |

**筛选功能**:
- 文件类型：全部 / 文档 / 音频 / Markdown
- 解析状态：全部 / 待解析 / 解析中 / 已完成 / 失败
- 搜索框：按文件名关键词搜索

**批量操作**:
- 批量解析待处理
- 批量索引向量
- 重试失败任务
- 清除已完成

## 5. 数据流程设计

### 5.1 数据合并策略

为了在同一视图中显示解析和索引状态，需要合并两个数据源：

```javascript
// 合并后的文件对象结构
{
  // 来自 parseStore
  id: Number,
  file_name: String,
  file_path: String,
  file_hash: String,
  parse_state: 'pending'|'running'|'done'|'failed',
  parser_type: 'mineru'|'audio',
  error_msg: String,
  created_at: Date,
  updated_at: Date,
  
  // 来自 vectorStore
  vector_state: 'pending'|'indexing'|'done'|'none',
  chunk_count: Number,
  indexed_at: Date,
  
  // 计算属性
  display_state: 'parsing'|'parsed'|'indexing'|'completed'|'failed'
}
```

### 5.2 状态映射

| 解析状态 | 向量状态 | 显示状态 |
|----------|----------|----------|
| pending | - | parsing:pending |
| running | - | parsing:running |
| failed | - | failed |
| done | none | parsed |
| done | pending | indexing:pending |
| done | indexing | indexing:running |
| done | done | completed |

## 6. 技术实现要点

### 6.1 状态管理

**现有 Store 保持不变**，只需要在组件层进行数据合并：

```javascript
// 在 FileManagementView.vue 中
const parseStore = useParseStore()
const vectorStore = useVectorStore()

// 计算属性：合并后的文件列表
const mergedFiles = computed(() => {
  const tasks = parseStore.tasks
  const indexedFiles = vectorStore.indexedFiles
  
  return tasks.map(task => {
    const indexedFile = indexedFiles.find(f => f.file_path === task.file_path)
    return {
      ...task,
      vector_state: indexedFile ? 'done' : (task.state === 'done' ? 'pending' : 'none'),
      chunk_count: indexedFile?.chunk_count || 0
    }
  })
})
```
