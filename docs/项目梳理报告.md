## 一、项目定位

**QBase** 是一款个人本地知识管理应用，用于管理播客音频、视频、文档三类知识资产，围绕这些内容提供统一查看、转录、AI 总结、笔记管理、三层搜索（文件名 / 全文 / 向量语义）等能力。

核心设计理念：**文件系统是唯一数据源，数据库只是索引缓存，CLI 模块无状态独立可用。**

| 层     | 技术栈                            |
| ----- | ------------------------------ |
| 前端    | Vue3 + Element Plus + Electron |
| 后端    | Python + FastAPI               |
| 数据库   | SQLite                         |
| 向量库   | LanceDB                        |

| 语音转文字 | SiliconFlow API                |

```

  ├── src/api/     # 后端 API 调用层
  ├── src/components/  # UI 组件（文件树、Markdown查看器、播放器等）
  └── src/stores/  # Pinia 状态管理

  ├── src/services/  # 业务服务（文件扫描、工作区、衍生品管理）
```

已实现功能包括：多工作区、文件树浏览、音频转录、PDF/文档解析、向量搜索、WebSocket 实时通信、论文模块等。

### 3.2 新版规划（PRD v1.0）

重构后的技术选型发生了重大变化：

| 维度   | 旧版                             | 新版（PRD v1.0）                |
| ---- | ------------------------------ | --------------------------- |
| 前端   | Vue3 + Electron + Element Plus | **NiceGUI**（Python Web GUI） |
| 后端   | FastAPI                        | FastAPI（保留）                 |

## 四、PRD v1.0 核心设计

### 4.1 核心概念

| 概念               | 说明                                                               |
| ---------------- | ---------------------------------------------------------------- |
| **Library（知识库）** | 一个本地目录，根目录下创建 `.knowledge/` 存放应用数据                               |
| **Asset（资产）**    | 原始文件：音频(.mp3/.m4a/.wav...)、视频(.mp4/.mkv...)、文档(.pdf/.md/.txt...) |
| **Artifact（产物）** | 派生文件：transcript / summary / note / parsed                        |
| **Task（任务）**     | 主应用触发的后台任务：transcription / summarization / scan / rebuild        |
| **Search Index** | 三层：SQLite LIKE（文件名）/ SQLite FTS5（全文）/ LanceDB（向量）                |

### 4.2 文件命名约定

派生文件与源文件同目录存放，点号分隔：

```
episode-001.mp3                  # 原始音频
episode-001.txt                  # 转录文本（兼容现有 CLI）
episode-001.transcript.txt       # 转录文本（规范命名）
episode-001.summary.md           # AI 总结
episode-001.notes.md             # 用户笔记
episode-001.parsed.md            # 文档解析结果（后续）
```

识别优先级：`.transcript.txt` > `.txt`

### 4.3 应用数据目录

```
.knowledge/
├── config.toml              # 应用配置
├── db.sqlite                # SQLite（资产/产物/任务/chunks/FTS5/缓存）
├── vector/lancedb           # LanceDB 向量数据
├── cache/embeddings.sqlite  # Embedding 缓存
├── backups/                 # 总结覆盖前备份
├── logs/
└── tasks/
```

### 4.4 架构设计

```
浏览器 (127.0.0.1:8765)
    ↓
NiceGUI UI 层
    ↓
FastAPI / Service Layer
    ↓
SQLite / LanceDB / File System
    ↓
Task Worker → CLI Runner (独立 venv) / OpenAI Compatible API
```

### 4.5 关键架构决策

1. **文件系统即数据库** — 数据库只是索引缓存，删除 `.knowledge/` 后可重新扫描恢复
2. **CLI 无状态** — 转录 CLI 只负责生成文件，主应用通过扫描发现结果
3. **双虚拟环境隔离** — 主应用和 CLI 模块使用不同 venv，避免依赖冲突
4. **OpenAI 兼容接口** — LLM 和 Embedding 统一走 OpenAI Compatible API，可接本地或云端
5. **不移动不重命名** — 应用不碰用户原始文件

### 4.6 第一阶段明确不做

文件监听、自动转录、应用内笔记编辑、PDF/DOCX 内容解析、JSON segments 字幕跳转、TTS、标签系统、混合搜索排序、sidecar 目录、打包 exe。

## 七、数据模型（PRD 定稿）

### 7.1 assets 表

```sql
CREATE TABLE assets (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  type TEXT NOT NULL,          -- audio / video / document
  relative_path TEXT NOT NULL UNIQUE,
  absolute_path TEXT NOT NULL,
  mime_type TEXT,
  size INTEGER,
  mtime INTEGER,
  file_hash TEXT,
  duration_seconds REAL,
  parse_status TEXT DEFAULT 'unknown',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 7.2 artifacts 表

```sql
CREATE TABLE artifacts (
  id TEXT PRIMARY KEY,
  asset_id TEXT NOT NULL,
  kind TEXT NOT NULL,          -- transcript / summary / note / parsed / meta
  relative_path TEXT NOT NULL UNIQUE,
  absolute_path TEXT NOT NULL,
  file_hash TEXT,
  mtime INTEGER,
  source TEXT,                 -- app / cli / external
  generator TEXT,
  model TEXT,
  status TEXT DEFAULT 'active', -- active / stale / ambiguous / orphan
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 7.3 其他表

- **tasks** — 任务记录（pending/running/success/failed/cancelled）
- **chunks** — 文本分块（用于全文索引和向量索引）
- **chunks_fts** — SQLite FTS5 全文索引虚拟表
- **embedding_cache** — Embedding 缓存（content_hash → vector）

## 九、总结

QBase 经历了一轮完整的 Vue3+Electron 开发后（307 commits, v1.2），决定推倒重来，转向纯 Python 技术栈（NiceGUI + FastAPI）。当前仓库处于设计文档完备、代码清空待重建的状态。

**优势**：

- PRD v1.0 极其详尽（35 个章节，覆盖数据模型、API 设计、里程碑、验收标准、风险应对）
- M0 骨架代码已就绪，可直接创建运行
- 参考文档齐全（LanceDB、Langchain、MinerU、SiliconFlow）

**风险**：

- NiceGUI 对于复杂知识管理界面的长期适用性待验证
- 从 Electron 降级到浏览器访问，牺牲了部分桌面体验
- 第一阶段不做文件监听和自动转录，用户体验有折损
