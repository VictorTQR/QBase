# v0.8 - 应用设置页面与 PDF 解析策略

**日期**: 2026-03-01  
**状态**: ✅ 已完成

---

## 概述

本次迭代完成了统一的应用设置页面，将分散的配置整合到一个独立的设置界面，并实现了可选择的 PDF 解析策略。

---

## 新增功能

### 1. 统一设置页面

**路由**: `/settings`

**特性**:
- 独立页面，带自定义 Header
- 左侧导航栏（LLM、PDF 解析、向量存储）
- 右侧内容区显示对应设置表单
- 左上角返回首页按钮（图标按钮）
- 二栏布局，响应式设计

### 2. PDF 解析策略选择

**策略选项**:
- `local` - 仅本地解析（pdf.js）
- `mineru` - 仅 MinerU 解析（默认）
- `auto` - 优先本地，失败降级 MinerU

**特性**:
- 预留扩展空间（提示「未来将支持更多解析方式」）
- 策略配置持久化到 LocalStorage
- MinerU 配置与解析策略同页管理

### 3. 配置模块拆分

将原 LlmConfigDialog 的配置拆分为三个独立模块：

| 模块 | 功能 |
|------|------|
| LLM 设置 | API 类型、Base URL、API Key、Model、测试连接 |
| PDF 解析 | 解析策略、MinerU 配置 |
| 向量存储 | SiliconFlow 配置、Embedding Model、ASR Model |

### 2. TextExtractor.js - 策略选择逻辑

```javascript
static async extractPdf(filePath, config = {}) {
  const strategy = config.parseStrategy || 'mineru'
  
  switch (strategy) {
    case 'local':
      return await this.extractPdfLocal(filePath)
    case 'mineru':
      if (!config.mineru?.apiKey) {
        throw new Error('MinerU API Key 未配置')
      }
      return await this.extractWithMinerU(filePath, config.mineru)
    case 'auto':
    default:
      // 原有的优先本地、失败降级逻辑
  }
}
```

### 3. 设置组件 - Watch 防循环机制

为解决「Maximum recursive updates exceeded」错误，所有设置组件都采用了 `isUpdating` 标志位：

```javascript
const isUpdating = ref(false)

watch(
  () => agentStore.llmConfig,
  (config) => {
    if (isUpdating.value) return
    isUpdating.value = true
    // 更新表单...
    setTimeout(() => { isUpdating.value = false }, 0)
  },
  { immediate: true, deep: true }
)

watch(form, (newForm) => {
  if (isUpdating.value) return
  isUpdating.value = true
  // 更新 store...
  setTimeout(() => { isUpdating.value = false }, 0)
}, { deep: true })
```
