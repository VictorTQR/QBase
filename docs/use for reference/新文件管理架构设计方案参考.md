## 1. 设计目标与原则
| 原则 | 说明 | 落地方式 |
|------|------|----------|
| 🔒 **数据主权** | 原始文件零侵入，AI 产物用户可直读/可编辑 | 派生数据以 Markdown/JSON 落盘，禁用沙盒存储 |
| 📦 **结构聚合** | 消除 IndexedDB/SQLite/LanceDB 数据孤岛 | 统一归入 `.qbase/` 目录，按文件哈希隔离 |
| 🔗 **强关联溯源** | 文件移动/重命名不断链，AI 结果精准定位 | `SHA-256 短哈希 + 相对路径` 双重锚定 |
| 🔄 **同步友好** | 兼容 Syncthing/iCloud/坚果云等双向同步工具 | 幂等操作、相对路径、冲突可重建 |
| ⚡ **渐进演进** | 遵循 KISS/YAGNI，不增加冗余复杂度 | 双写过渡 → 平滑替换 → 废弃旧存储 |

## 3. 目录结构与数据流向
### 3.1 标准目录规范
```
📂 用户工作区/
├── 📄 论文/报告/教程/ (用户自由管理，应用仅读)
└── 📦 .qbase/                     ← 应用专属目录（默认隐藏）
    ├── ⚙️ config.json             ← 模型配置、开关、同步策略
    ├── 🗄️ metadata.db             ← SQLite：文件索引、派生关系、任务队列
    ├── 🤖 generated/              ← AI 派生数据（按源文件哈希隔离）
    │   ├── a1b2c3d4e5f67890/      ← 文件短哈希目录
    │   │   ├── raw_text.md        ← 解析后纯文本
    │   │   ├── ai_notes.md        ← AI 生成的笔记
    │   │   ├── flashcards.json    ← 闪卡数据
    │   │   ├── mindmap.json       ← 思维导图结构
    │   │   └── transcript.srt     ← 音视频转录
    │   └── ...
    ├── 🔍 indexes/
    │   ├── vector.lance           ← LanceDB 向量库
    │   └── fulltext/              ← 全文索引 (Tantivy/FTS5)
    └── ⚡ cache/                  ← 缩略图、临时分块、模型缓存
```

### 3.2 数据处理流
```
用户添加/修改文件
       ↓
Electron 主进程：计算 mtime/size → 快速过滤 → 写入 metadata.db (status=pending)
       ↓
FastAPI 任务队列：拉取 pending 任务 → 解析/转录 → 生成 raw_text.md & derivatives
       ↓
写入 .qbase/generated/{hash}/ → 更新 derivatives 表状态
       ↓
向量化/全文索引 → 更新 LanceDB/Fulltext → 广播 WebSocket
       ↓
前端 Vue 按需拉取 → UI 渲染 / 支持本地编辑器直改
```

## 4. 核心机制设计
### 4.1 文件标识与追踪
| 字段 | 类型 | 说明 |
|------|------|------|
| `file_hash` | `TEXT` | `SHA-256` 前 16 字符，全局唯一主键 |
| `rel_path` | `TEXT` | 相对工作区路径，解决跨设备路径差异 |
| `mtime` | `INTEGER` | 文件最后修改时间戳，用于增量检测 |
| `status` | `ENUM` | `pending | processing | ready | error | missing | orphan` |

**工作流程**：
1. **快速扫描**：仅比对 `rel_path + mtime + size`，命中则跳过
2. **精准校验**：任务执行前或定期后台计算哈希，标记 `dirty`
3. **断链恢复**：启动时校验 `rel_path` 是否存在，不存在则标 `missing`，提供「重新链接」向导

### 4.2 派生数据生命周期
- **创建**：AI 任务完成 → 写入 `{hash}/xxx.md/json` → `derivatives` 表记录版本/模型/时间
- **更新**：源文件变更 → 派生数据自动标记 `outdated` → 用户触发或后台异步重生成
- **删除**：源文件删除 → 派生数据标记 `orphan` → 提供 `清理/归档/保留` 选项
- **同步**：`.qbase/` 可整体同步。冲突时优先保留高版本，向量索引支持 `--rebuild` 安全重建

### 4.3 变更检测策略
```python
# 伪代码：高效增量检测
def scan_workspace(root_path):
    # 1. 读取上次快照
    last_scan = load_metadata_snapshot()
    
    # 2. 文件系统快速比对 (mtime + size)
    current_files = walk_with_stats(root_path)
    changed = diff_by_mtime_size(last_scan, current_files)
    
    # 3. 对变更文件按需计算哈希 (避免大文件全量扫描卡顿)
    for f in changed:
        f.hash = compute_sha256_prefix(f.path, length=16)
        f.status = 'pending'
        upsert_to_db(f)
    
    # 4. 触发后续解析任务
    dispatch_parse_queue()
```

## 5. 存储层重构方案
### 5.1 SQLite 核心 Schema (`metadata.db`)
```sql
CREATE TABLE files (
    hash        TEXT PRIMARY KEY,
    rel_path    TEXT UNIQUE NOT NULL,
    file_type   TEXT,          -- md | pdf | audio | video
    size        INTEGER,
    mtime       INTEGER,
    status      TEXT DEFAULT 'pending',
    created_at  INTEGER,
    updated_at  INTEGER
);

CREATE TABLE derivatives (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    file_hash   TEXT REFERENCES files(hash) ON DELETE CASCADE,
    type        TEXT,          -- raw_text | transcript | notes | flashcards | mindmap | analysis
    version     INTEGER DEFAULT 1,
    model_used  TEXT,          -- siliconflow/qwen/whisper 等
    status      TEXT DEFAULT 'ready',
    created_at  INTEGER
);

CREATE TABLE tasks (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    file_hash   TEXT REFERENCES files(hash),
    task_type   TEXT,          -- parse | embed | generate | sync
    status      TEXT,          -- queued | running | success | failed
    progress    REAL DEFAULT 0,
    error_msg   TEXT,
    created_at  INTEGER
);
```

### 5.2 替换 IndexedDB 策略
| 原存储 (Dexie) | 新方案 | 前端改造 |
|----------------|--------|----------|
| 提取文本缓存 | `.qbase/generated/{hash}/raw_text.md` | 通过 `/api/files/{hash}/raw` 按需拉取 |
| 会话状态/设置 | `LocalStorage` + `config.json` | 启动时合并云端/本地配置 |
| 临时大对象 | 移除，改为流式 API + 内存 LRU 缓存 | 取消 Dexie 依赖，减少包体积 |

**迁移脚本逻辑**：
1. 遍历 Dexie 表，导出 `{path, text, metadata}`
2. 计算文件哈希，写入 `metadata.db`
3. 文本落盘至 `generated/{hash}/raw_text.md`
4. 清理 Dexie 数据库，标记迁移完成

### 5.3 向量库关联增强 (LanceDB)
```json
// LanceDB 表结构增强
{
  "id": "a1b2c3d4_chunk_02",
  "file_hash": "a1b2c3d4",
  "text": "...核心段落...",
  "vector": [0.12, -0.45, ...],
  "metadata": {
    "chunk_idx": 2,
    "start_time": 124.5,  // 音视频
    "page": 3,            // PDF
    "source_type": "pdf"
  }
}
```
**检索溯源**：RAG 返回时附带 `citations: [{file_hash, start_time, page, text}]`，前端点击直接定位。

## 8. 风险评估与应对预案
| 风险 | 影响 | 应对方案 |
|------|------|----------|
| **大文件哈希导致启动卡顿** | 用户体验下降 | 采用 `mtime+size` 快速过滤；哈希计算移至后台队列；支持手动触发全量校验 |
| **用户频繁移动/重命名文件** | 索引断裂、AI产物孤立 | 相对路径存储；启动时扫描并提示重新关联；提供 `orphan` 数据回收站 |
| **跨设备同步产生向量库冲突** | 检索结果不一致 | LanceDB 支持追加写入；提供 `--rebuild` 安全重建指令；同步工具排除 `cache/` |
| **迁移过程中数据丢失** | 知识库损坏 | 迁移前自动备份 `.qbase/migration_backup/`；校验文本行数与哈希一致性；失败可回滚 |
| **前端状态管理混乱** | 渲染错误、内存泄漏 | 严格划分 `Pinia Stores` 职责；文本按需加载+LRU缓存；取消全局大状态 |
